# Review of draftwright-rust at 971e17e (2026-10-08)

A whole-repository review (architecture, correctness, tests, maintenance, code) run while the
maintainer was away. Reviewers' findings were merged where they overlapped and re-checked before
being recorded here; each says what was confirmed (re-run or read in the code) and what is the
reviewer's measurement only. The improvement plan at the end is what the next waves do about
them. Anything that needs a maintainer decision is listed as a question, not decided.

## High

### H1. `review`'s lint never sees the port's own callouts, so it reports every drawn hole callout as missing, and a test locks this in

- **Evidence:** `src/model.rs:806` always builds the Drawing with `annotations: Vec::new()`;
  `dims::render` pushes ink and text runs but no `Annotation`; `lint::marks` reads only
  `drawing.annotations` (`src/lint/mod.rs:105-121`). Re-run on `plate.step` with `plate.json`:
  plan places `4× ⌀6 THRU (2×2)`, and review on the same part returns
  `hole_requirement_missing`, whose fix asks for "a hole callout reading \"4× ⌀6 THRU\"".
  `tests/lint.rs:484-513` (`review_reports_the_plates_unstated_holes`) asserts these three false
  findings; its doc comment ("which the port does not dimension yet") went stale when stream A
  merged (5b7be0d). Reviewer corpus counts (ctc01 9, cgb245 15, …) not re-run.
- **Plan:** `dims::render` pushes one `output::Annotation` per placed `PlannedDimension` (name =
  ID, view, runs = the text runs it pushed, claims = its measurements). Claims are provenance on
  the Drawing, so R4's lint independence holds. The plate test expects no hole findings under
  the default spec; a negative case omits `d:f:hole_pattern:1/bore.diameter@plan` and the
  findings return.

### H2. dims reads the wrong countersink keys, so every countersunk hole is refused a callout

- **Evidence:** `dims::hole` calls `sized(p, "csink", "angle")` (`src/dims.rs:387`), reading
  `csink.diameter` and `csink.angle`; lint (`src/lint/holes.rs:84`) reads `major_diameter` and
  `included_angle`, the field names in quiddity's record (`countersinks.py:86-88`). A hole with a
  non-null csink fails with `feature_not_dimensioned` while lint demands its countersink sizes.
  No fixture has a non-null csink.
- **Plan:** read `major_diameter` and `included_angle`; a countersunk-hole fixture covering dims
  and lint.

### H3. A zero-span projected NURBS piece panics the whole render or review (cgb242 cannot be drawn)

- **Evidence (re-run):** `draftwright review cgb242.step` panics at `src/output.rs:56:42`
  ("index out of bounds: the len is 0 but the index is 0") and answers `failed`.
  `bezier_pieces` (`output.rs:854-887`) with t0 == t1 dedups the breaks to one value, so
  `windows(2)` yields no piece, and `Curve::start`/`end` (`output.rs:56`, `72`) index an empty
  `Vec`. One degenerate hidden edge loses the whole drawing.
- **Plan:** build no curve for a zero-span exact piece or a polyline of fewer than 2 points, and
  count dropped edges in a problem; unit test for `bezier_pieces` with t0 == t1; cgb242 as a
  regression. The zero-span HLR piece is recorded as a haecceity question.

### H4. SVG and PDF draw Bézier pieces of degree 4 or more wrongly

- **Evidence (read in the code):** `polynomial` (`output.rs:746-751`) passes an equal-weight piece
  of any degree; `svg_segments` (`1002-1011`) writes `C` followed by all n poles, malformed for
  n ≠ 3; `pdf_curve`'s `_` arm (`1125-1127`) draws `cubic_to(p[1], p[2], p[3])` and drops
  `p[4..]`, including the true end point. The reviewer's count (118 malformed paths on
  nist_ctc_04) was not re-run.
- **Plan:** equal-weight pieces of degree > 3 take the chord path rational pieces use; assert
  `p.len() == 4` in the `_` arms; a degree-5 unit test checking SVG command arity and the PDF
  end point.

### H5. DXF bytes depend on the host time zone, breaking R1 invariant 7

- **Evidence (re-run):** `src/output.rs:304-312` pins the header dates with `chrono::Local`
  2000-01-01. On `plate.step` with features the DXF sha1 is 50ec7031… under `TZ=UTC` and
  0bd97176… under `Asia/Kolkata`; the SVG is identical. The determinism tests
  (`tests/model.rs:134-152`) run in one process and zone.
- **Plan:** construct the local value so the dxf crate's local-epoch subtraction yields a fixed
  Julian date in every zone; a test running the binary under two `TZ` values comparing SVG, DXF
  and PDF bytes.

## Medium

- **M1. Corpus-backed tests pass silently without the corpus, and there is no CI.** No
  `.github`; `tests/common/corpus.rs:14-21` returns `None` for a missing path, and bands, views,
  dimensions, lint (×2) and sections print SKIPPED and pass; the lookup is copied in
  `dimensions.rs` and `lint.rs`. Plan: one helper honouring `DRAFTWRIGHT_CORPUS_REQUIRED=1`,
  used everywhere and named in the verify line; a CI workflow. haecceity comes by git from the
  private `pzfreo/quiddity` (Cargo.toml line 12, `branch = "prototype/rust-port"`, pinned
  in Cargo.lock), so CI needs a read credential: a maintainer question.
- **M2. Hole records are parsed three times with divergent rules; lint's pattern grouping ignores
  the recognised patterns on a stale premise.** `demand::axis_of` accepts |cos| > 0.99
  (`demand.rs:80-83`), `dims::principal` needs 1e-6 relative (`dims.rs:238-241`); lint keys
  sizes at 1e-3 (`holes.rs:88-90`), dims at 1e-6 (`dims.rs:243`). `lint/holes.rs:240-242` says
  the Analysis does not name a hole's pattern, but `Analysis.recognition.patterns` exists and
  dims uses it; lint never reads it. Plan: one typed hole reader, one principal-axis predicate,
  one size resolution; lint groups by `recognition.patterns` when present.
- **M3. Dimension placement does not use the reserved view bands.** dims places side-view
  horizontal dimensions Below (`dims.rs:1243-1244`) while layout gives the side view
  `bottom: strips.sv_bottom`, default 0 (`layout.rs:553`, `202`); dims never reads
  `PlannedView.area`; no test names `annotation_off_sheet`, `annotation_over_view` or
  `annotation_ink_overlap`. Plan: reserve side-view lanes from demand (as `fv_bottom` does), a
  ratchet of per-part placement problem codes with verdicts, and a test that placed ink lies in
  its view's area or is reported.
- **M4. Across a revision mismatch, feature-keyed dimension entries are applied blindly** while
  the info problem says only view choices carry over (`model.rs:372-384`); feature IDs are
  rank-based and renumber. Contradicts R3 invariants 1–3. Plan: keep feature-keyed entries
  inactive across a sha mismatch and list them in a warning problem; test.
- **M5. Section A–A is dropped silently** when the plan view is omitted or cannot be planned
  (`model.rs:450-453`). Plan: a `section_not_shown` problem saying why and how to fix it, also
  when `spec.views` names `section_aa` and demand has none; tests.
- **M6. Silent fallbacks at the edit, spec-recovery and output-path boundaries.** `edit`'s
  `remove` of an absent key succeeds and creates parents (`model.rs:659-672`); `embedded_spec`
  ends in `.ok()` (`988`), so a corrupt spec reads as none; the SVG branch's `?` (`965-968`)
  returns `None` instead of falling through and cuts at the first marker even inside CDATA;
  `api::write` uses `with_extension` (`api.rs:152`), so `part.rev2` and `part.rev3` both write
  `part.svg`. Plan: refuse those, `Result<Option<Spec>>`, choose the branch by file signature,
  escape `<` in the embedded JSON, append the extension to the file name.
- **M7. Docs and catalogue status are stale or untruthful.** `README.md:54` says "dimensions and
  annotations come next"; README and `docs/next-session.md` predate the dims, lint and section
  merges; README usage omits `--features`; `ISSUE-1262-a` is `ported`
  (`docs/rules/issues.yaml:1404`) though its note says the Rust veto is narrower and waits for
  dimensions and lint, so by the catalogue rules it is pending with `rust_note`; Rust remarks sit
  in `port_note` rather than `rust_note` (ISSUE-1262-a; ADR2-D4 and ADR2-13 per the reviewer).
  `next-session.md` also describes quiddity-rust at 590cb89 with 22 families and no
  correspondence (it is at 2fa7207, 28 entry points, correspondence implemented in the library
  and CLI); `docs/model.md:65` says Rust quiddity's JSON carries no faces.
- **M8. Feature kinds with no dimension planner leave no trace.** `dims::wants`
  (`dims.rs:429-922`, 495 lines) handles only the envelope, turned steps and holes; fillets,
  chamfers, bosses and slots get no problem. Plan: one info problem per feature of an unplanned
  kind; split `wants()` per family as families land.
- **M9. plan, review and render re-analyse the STEP on every call** (`api.rs:92-95`), unlike
  `docs/model.md`'s `plan(Analysis, Spec)`. Accepting an Analysis or memoising by sha256 is a
  maintainer question.
- **M10. Fingerprints are owned twice, contrary to R3.** `bridge.rs` defines its own; quiddity-rust
  now has `correspondence::fingerprint`, but its `Features` derives only `Serialize`. No spec
  stores a fingerprint yet. A maintainer question before stage 4 writes anchors.

## Low

- **L1. Lint and dims disagree on edge cases:** dims prints a spotface with ⌴ (`dims.rs:301-306`,
  ignoring the role) while lint's fix text uses "SF" (`holes.rs:150`); lint defaults a missing
  depth to NaN (`holes.rs:80`), giving "bore.depth (NaN)"; dims refuses even a through hole
  without depth (`dims.rs:384`).
- **L2. Kernel and analysis failures are coded `invalid` rather than `failed`**
  (`api.rs:87`, `93`); a haecceity area discrepancy (ctc04) exits 2 as an invalid request.
- **L3. Duplicated font, constants and contradictory messages:** the same TTF embedded twice
  (`api.rs:23`, `dims.rs:58`); dims ignores `model::render`'s font parameter;
  `fonts/IBMPlexSansCondensed-Regular.ttf` unreferenced; text height, arrow size and view tables
  repeated as literals; `Problem.severity` a `String` while lint has an enum.
- **L4. Test-quality leftovers:** `tests/facts.rs:29-30` asserts a tautology; two recognition
  fixture sets in use (`recognition/corpus/` for views, bands and sections; `sheets/` for
  dimensions and lint) from different quiddity versions; the haecceity update procedure
  (`cargo update -p haecceity`) is undocumented.

## Strengths

- Thin adapters: CLI, JSON-lines and MCP all go through `api::call`, which catches panics and
  answers `failed` with structured errors (the cgb242 run returned `failed` rather than killing
  the process).
- Renderers draw only from the plan by construction, with a test that changes a label and checks
  the drawing follows (R1 invariant 2).
- Lint is independent of Plan and Spec, enforced by a guard test with its own self-test (R4
  decision 1); rules are separate from mark extraction, so the annotations fix fits the design.
- The bridge fails honestly: sha256 plus per-face surface type and area binding; unhomed record
  types are refused.
- Known-difference lists (views, bands, dimensions, lint) are checked both ways with verdicts.
- Determinism by construction in-process: BTreeMap/BTreeSet, `total_cmp`, no HashMap or threads;
  SVG output identical across time zones.
- Doc comments name the mirrored Python function or rule ID.
